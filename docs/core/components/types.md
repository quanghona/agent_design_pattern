# Types

## Overview

The `types` module defines the foundational data structures and abstract base classes that form the backbone of the AI Agent Pattern framework. Every component — from agents and chains to orchestrators and retrievers — communicates through a unified message object (`AgentMessage`) and conforms to a consistent interface contract (`BaseChain`, `BaseLLMChain`). This module ensures type safety and interoperability across all packages in the ecosystem.

## Architecture

The types module sits at the lowest level of the component hierarchy. It provides the building blocks that all other components depend on:

- `AgentMessage` is the universal message object passed between all components
- `BaseChain` and `BaseLLMChain` define the abstract interface that all chain implementations must follow
- `TokenUsage` and `ContentType` are supporting types used throughout the framework

## Key Concepts

### AgentMessage

The `AgentMessage` class is the central data structure in the framework. It carries all information needed for an agent to process a request and produce a response. Every component in the system receives and returns `AgentMessage` objects, ensuring a uniform interface across all abstractions.

#### Fields

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `query` | `str` | *(required)* | The user query consumed by the agent's LLM. System prompts and user templates are not stored here, as each agent manages its own. |
| `query_media` | `List[Tuple[ContentType, str]] \| None` | `None` | Media content (images, audio, video) associated with the query. |
| `origin` | `str \| None` | `None` | The name of the agent that sent this message, used for tracking message provenance. |
| `responses` | `List[AgentResponse]` | `[]` | All responses generated by the agent. Each response is a tuple of `(agent_name_or_index, response_text)`. Supports multiple responses from the same or different sub-agents. |
| `context` | `dict \| None` | `None` | Additional material from other agents or user input. The consuming prompt must explicitly know the expected format of this context. |
| `execution_result` | `Literal["success", "error"] \| None` | `None` | Whether the agent execution succeeded or encountered an error. |
| `error_message` | `str \| None` | `None` | The error message if `execution_result` is `"error"`. |
| `media` | `List[Tuple[ContentType, str]] \| None` | `None` | Additional media content produced by the agent (images, video, audio, etc.). |
| `token_usage` | `Dict[str, TokenUsage \| List[TokenUsage]] \| None` | `None` | Token usage statistics from the LLM(s). The dictionary key is managed by the implementing chain class. |

#### Serialization Methods

`AgentMessage` provides three methods for converting the message to other formats:

- **`to_dict()`** — Converts the message to a dictionary. Nested `context` dictionaries are flattened with a `context_` prefix (e.g., `context_a`, `context_b`). None values are excluded.
- **`dump_json()`** — Serializes the message to a JSON string using `to_dict()`.
- **`flatten_dict()`** — Internal helper that flattens a nested dictionary into a single-level dictionary with a configurable separator.

### BaseChain

The `BaseChain` abstract base class defines the minimal interface for any chain component. It requires implementing `__call__`, which takes an `AgentMessage` and returns a transformed `AgentMessage`.

### BaseLLMChain

The `BaseLLMChain` extends `BaseChain` with additional functionality specific to LLM-based chains:

- **`invoke(message, **kwargs)`** — The primary abstract method for chain logic. Override this to implement custom chain behavior.
- **`ainvoke(message, **kwargs)`** — Async version of `invoke`. By default, delegates to the synchronous `invoke`. Override for true async implementations.
- **`name`** — A descriptive name for the chain, typically matching the agent that holds it.

#### Token Usage Tracking

Each integration framework provides its own mechanism for tracking token usage:

| Framework | Source |
|-----------|--------|
| **LangChain** | `AIMessage.usage_metadata` property |
| **LlamaIndex** | `get_tokens_from_response` utility function |
| **DSPy** | Enable with `dspy.context(track_usage=True)` or `dspy.configure()`, then call `.get_lm_usage()` on response objects |
| **Transformers** | Compute from the output tensor shape (length of token IDs) |

Each integration package provides a `token_from_response` utility to convert framework-specific token objects into the unified `TokenUsage` format.

### Supporting Types

| Type | Description |
|------|-------------|
| `ContentType` | Literal type for media content: `"text"`, `"image"`, `"audio"`, `"video"`, `"document"` |
| `AgentResponse` | Type alias for `Tuple[str, str]` — `(agent_name, response_text)` |
| `TokenUsage` | TypedDict with `input_tokens`, `output_tokens`, and `total_tokens` (all `int`) |
| `ChainMessage` | TypeVar for chain-specific message types |
| `ChainResponse` | TypeVar for chain-specific response types |

## Usage

### Basic Example: Creating and Serializing an AgentMessage

```python
from aap_core import AgentMessage

# Create a message with a query
message = AgentMessage(query="What is the capital of France?")

# Add responses
message.responses = [("my-agent", "The capital of France is Paris.")]
message.execution_result = "success"

# Serialize to dictionary (context is flattened with 'context_' prefix)
msg_dict = message.to_dict()
# {'query': 'What is the capital of France?', 'responses': [('my-agent', 'The capital of France is Paris.')], 'execution_result': 'success'}

# Serialize to JSON
json_str = message.dump_json()
```

### Advanced Example: Message with Context and Media

```python
from aap_core import AgentMessage

# Create a message with nested context
message = AgentMessage(
    query="Summarize the research findings",
    context={
        "retrieved_docs": [
            {"title": "Paper A", "score": 0.95},
            {"title": "Paper B", "score": 0.87},
        ],
        "user_preferences": {"length": "short", "tone": "formal"},
    },
    query_media=[("image", "/path/to/image.jpg")],
)

# to_dict() flattens the nested context
msg_dict = message.to_dict()
# {
#   'query': 'Summarize the research findings',
#   'context_retrieved_docs': [{'title': 'Paper A', 'score': 0.95}, ...],
#   'context_user_preferences': {'length': 'short', 'tone': 'formal'},
#   'query_media': [('image', '/path/to/image.jpg')]
# }
```

### Advanced Example: Custom LLM Chain

```python
from aap_core import AgentMessage, BaseLLMChain

class MyLLMChain(BaseLLMChain):
    def __init__(self):
        super().__init__(name="my-llm-chain")

    def invoke(self, message: AgentMessage, **kwargs) -> AgentMessage:
        # Process the message — e.g., call an LLM
        response_text = f"Processed: {message.query}"
        message.responses.append(("my-llm-chain", response_text))
        message.execution_result = "success"
        return message

# Use the chain
chain = MyLLMChain()
result = chain.invoke(AgentMessage(query="Hello"))
print(result.responses)  # [("my-llm-chain", "Processed: Hello")]
```

## Configuration

The types module does not have configurable parameters. Configuration is handled at the component level (e.g., `BaseLLMChain.name`).
